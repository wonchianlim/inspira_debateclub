**文档状态：** Phase 0 草案，等待产品负责人确认
**对应规范：** `INSPIRA_DEEPSEEK_MASTER_SPEC.md` 第 5.4 节、第 1.1 节、第 17 节、Appendix F
**资料核实日期：** 2026-09-29
**读者：** 非技术产品负责人 + 后续实现者

> **本文的性质说明：** 云产品的区域、价格与法规会变化。规范 Appendix F 明确要求"在 Phase 0 重新核实当前官方文档并记录访问日期"。
> 本文严格区分**已核实的官方事实**与**仍需你亲自确认的事项**。凡是未经核实的内容，本文都会明确标注，不会用猜测冒充事实。

## 1. 这份文档要决定什么

三件事：

1. **应用服务器放在哪个国家/地区的哪个区域**（规范要求必须是香港或新加坡的明确区域）；
2. **数据库与登录服务放在哪里**（托管 Supabase 新加坡，还是同区域的自建方案）；
3. **从中国大陆能不能正常使用** —— 这是规范第 1.1 节的验收标准，必须**实测**，不能靠推测。

**这三件事在 Phase 1 之前必须有结论**，因为数据库方案会影响数据库结构（见 `docs/schema.md` 第 5 节末尾与 `docs/decisions/0001`）。

## 2. 已核实的官方事实

以下内容来自官方文档，附访问日期。

### 2.1 Supabase 的区域（已核实）

| 事实 | 内容 |
|---|---|
| 新加坡专属区域 | **存在**，区域代号 `ap-southeast-1`（Southeast Asia (Singapore)） |
| 新加坡"通用区域" | 也存在一个 APAC 通用区域，名称为 Southeast Asia (Singapore) |
| **香港区域** | **不存在**。Supabase 官方区域列表中没有香港 |
| 区域的含义 | 所选区域同时决定"项目数据存放在哪里" |

来源：Supabase 官方文档 "Available regions"，访问日期 2026-09-29。

**这条事实的直接后果：** 如果使用托管 Supabase，数据库与认证**只能在新加坡**。规范第 5.1 节说得很准确——"截至本文件更新时，Supabase 没有香港托管区域"。这与"应用服务器放香港"会产生**跨区域**的服务器到数据库通信（香港 ↔ 新加坡）。规范第 5.4 节要求："尽可能让应用计算与主数据库处于同一区域；如果不同区域，必须测量延迟并记录原因。"

Supabase 官方还提醒：**选择区域是数据存放位置的控制手段，不等于合规证明**。

### 2.4 ICP 备案（已核实，且结论明确）

Alibaba Cloud 官方文档原文：

> **Servers in the Chinese mainland require an ICP filing.**（中国大陆境内的服务器需要 ICP 备案）
> **Servers outside the Chinese mainland do not require an ICP filing.**（中国大陆境外的服务器**不需要** ICP 备案）

来源：Alibaba Cloud 官方文档 "Simple Application Server: Usage notes"，文档最后更新日期 2026-04-01，访问日期 2026-09-29。

**需要注意：** "不需要备案"是**技术上不需要**。规范第 5.4 节明确提醒：法律与备案义务取决于实际服务、主体、内容、用户与网络资源。**不要把"不用备案"理解成"一定合规"。**

### 2.5 一个重要的产品选择提醒（已核实）

同一份 Alibaba Cloud 官方文档还说明：

> 简单应用服务器（Simple Application Server）面向**低流量**工作负载；**公网带宽不保证**，高峰时段可能被限速或丢包；如果应用需要稳定、高质量的网络连接，应改用 **ECS 配合按带宽计费**。

**这条对本项目很关键。** 规范第 1.1 节把"大陆用户能正常使用"列为成功标准，而便宜套餐的带宽质量恰好是不保证的。**建议把 ECS（而非轻量/简单应用服务器）作为主要候选**，并在实测中验证带宽表现。

## 5. 费用

### 5.1 诚实的说明

**本文不给出具体价格数字**，原因有两个：

1. 云厂商的价格页是动态报价（受活动、计费方式、购买时长、汇率影响），**无法从文档中稳定获取**；
2. 把不确定的价格写成确定的事实，会让你在付款时产生错误预期——这比不给数字更糟。

**你要在购买前自己看一眼官方报价页**，下面给出确切位置。

### 5.2 官方报价页（请自行查看）

| 项目 | 官方链接 |
|---|---|
| 阿里云价格计算器 | https://www.alibabacloud.com/pricing-calculator |
| 腾讯云 CVM 价格计算器 | https://intl.cloud.tencent.com/pricing/cvm |
| Supabase 价格页 | https://supabase.com/pricing |
| 域名 | 由你选择的注册商报价（通常按年计费） |

### 5.3 费用由哪几部分组成

| 组成部分 | 说明 | 是否必须 |
|---|---|---|
| 云服务器（ECS/CVM） | 按配置与带宽计费，通常**按月或按年** | 必须 |
| 公网带宽 | 香港/新加坡到大陆的带宽是主要成本项；"按带宽计费"与"按流量计费"价格差别很大 | 必须 |
| 数据库与认证 | Supabase 通常有免费额度，超出后按月计费；付费套餐通常**按月** | 必须（或自建） |
| 域名 | 按**年**计费 | 必须 |
| SSL 证书 | 通常可用免费证书 | 可选 |
| 邮件服务 | 多数按量计费，通常有免费额度 | 必须（Phase 9） |

### 5.4 会触发"持续扣费"的情况（务必注意）

- **服务器按月/按年续费**：到期不续费服务会停止；
- **按流量计费的带宽**：访问量增大时费用会上升，**没有固定上限**；
- **Supabase 超出免费额度**：例如数据库容量、月活用户数、文件存储超出后开始计费；
- **域名到期未续**：域名可能被他人抢注。

**规范要求：** 任何购买、续费、涨价前，都必须先取得你的明确同意（`AGENTS.md` 的 Beginner Guidance Rules）。

### 5.5 非官方参考信息（**未核实，仅供参考**）

搜索结果显示阿里云社区文章提到香港服务器有"25 元/月起"一类的促销价。**这属于第三方/营销内容，不是官方报价，且促销随时变化。** 请勿以此作为预算依据，一切以 5.2 节的官方页面为准。

## 6. 中国大陆访问现实（务必先读这一节）

### 6.1 核心事实

**服务器放在香港或新加坡，不等于大陆用户一定能稳定访问。** 规范第 5.4 节对此有明确表述，本文完全同意。

原因：

- 流量需要**跨境**，受国际出口带宽与路由影响；
- 高峰时段（尤其是晚间）跨境链路质量波动明显；
- 不同运营商（电信/联通/移动）表现差异很大；
- 规范的准确说法是：**"能从中国访问"是一个工程验收测试，而不是"网站永远不会被干扰"的承诺。**

### 6.2 生产页面绝对不允许依赖的东西

规范第 5.4 节列出的禁止项（**这是硬性验收标准**）：

- Google Fonts、Google Analytics、Google reCAPTCHA 或任何 Google 托管资源；
- GitHub、npm、unpkg、jsDelivr 等公共 CDN；
- 任何未通过大陆测试的第三方 JS、字体、图片、地图、聊天控件、分析服务；
- 服务商的临时预览域名。

**做法：** JS/CSS 随应用一起打包、字体自托管、静态资源由自有域名提供、在自托管品牌字体通过审核前使用系统字体。构建时可以从外部源下载依赖，但**生产页面加载**不能依赖它们。

> 这正是为什么建议启用 Chrome DevTools MCP：它能在验收时**实测**页面到底请求了哪些域名，而不是靠人工检查代码。

### 6.3 CDN 与备案的注意点

- 香港/新加坡服务器一般**不使用大陆境内的托管资源**，因此与"把网站放在大陆服务器上"不是一回事；
- **不要**在没有核实当前 ICP/PSB 备案要求并取得专业意见之前，启用大陆 CDN 节点或把生产环境搬进大陆；
- 非大陆部署可能较慢或较不稳定，因为流量需要过境；
- "全球加速"类产品可能需要额外合同或跨境资质。

### 6.4 隐私与未成年人（必须由你决定）

系统存储学生（可能包含未成年人）的信息，并可能跨境传输数据。规范第 5.4 节要求：**在使用真实学生数据之前，必须取得一次合格的隐私/法律审查**，覆盖同意、隐私告知、保留期限、访问控制、事件响应，以及涉及中国大陆、香港、新加坡的跨境数据处理。

助手可以准备清单，但**不能**声称已合规。

## 7. Phase 0 连通性验证步骤（照做即可）

规范第 5.4 节要求在做完整实现之前，先部署一个**最小的试验页面**并完成以下测试。这一步通过之前，不得确定生产架构。

> **前提：** 以下步骤会创建**付费资源**。开始前必须先取得你的明确同意，并确认预算。
> **执行者：** 由你在大陆完成（你已确认可以自己完成）。
> **最终成果：** `docs/deployment-regions.md` 第 9 节会被填上真实记录。

### 准备阶段（助手做）

1. 助手准备一个**最小的、一次性的**试验页面，包含：一个首页、一个注册/登录流程、一个已认证的读写接口、一封测试邮件。代码与生产实现完全隔离。
2. 助手把页面部署到**第一个候选区域**（建议先测香港）。
3. 助手告诉你确切的网址、测试账号，以及要记录什么。

### 测试记录表（每次测试都填一行）

| 项目 | 要记录的内容 |
|---|---|
| 日期与时间 | 例如 2026-10-05 20:30 |
| 城市/省份 | 例如 广东深圳 |
| 网络运营商 | 例如 中国电信宽带 / 中国移动 4G |
| 设备 | 例如 Windows 笔记本 Chrome / iPhone |
| 是否使用 VPN | **必须为"否"** |
| 结果 | 每一步的通过/失败，以及失败时的现象 |
| 证据 | 截图（**必须遮住密码与密钥**） |

### 第 1 步：域名解析与 HTTPS 证书

**你要做：** 在电脑浏览器打开试验页面网址。
**成功时你会看到：** 地址栏显示**锁形图标**（表示 HTTPS 正常），页面正常显示，**没有**"连接不安全"警告。
**如果失败：** 把浏览器显示的完整错误文字截图发给我（不要自己改设置）。
**要记录：** 是否能打开、耗时大约几秒、有无警告。

### 第 2 步：不使用 VPN 打开首页

**你要做：** 确认**没有**开 VPN，按 F5 刷新三次。
**成功时你会看到：** 三次都能正常显示。
**要记录：** 每次的加载时间（可以用手机秒表）。

### 第 3 步：确认没有请求被拦截的第三方资源

**你要做：**

1. 在页面上按 **F12** 打开开发者工具；
2. 点 **Network（网络）** 标签；
3. 按 **F5** 刷新页面；
4. 等待页面加载完成；
5. 查看列表里**所有请求的域名**。

**成功时你会看到：** 请求的域名**只有你自己的域名**（以及可能的邮件/数据库域名，且这些不应由浏览器直接请求）。**不应出现** google、gstatic、fonts.google、cdn.jsdelivr、unpkg、github 等字样。
**如果失败：** 把网络面板截图发给我，并在截图上标出可疑的域名。
**要记录：** 是否有失败（红色）的请求，以及失败请求的域名。

### 第 4 步：注册、登录、登出、重置密码、会话保持

**你要做：** 依次完成六个动作：

1. 用测试邮箱**注册**；
2. **登录**；
3. **登出**；
4. 点"**忘记密码**"，去邮箱收信，点邮件里的链接，设置新密码；
5. 用新密码**重新登录**；
6. 登录后**等待 10 分钟不要操作**，然后点一下页面里需要登录才能看的区域。

**成功时你会看到：** 六步全部成功。第 4 步的邮件链接打开的是**你自己的域名**（不是别的域名）。第 6 步不会把你踢回登录页。
**如果失败：** 记录卡在哪一步、屏幕上的完整提示文字。
**要记录：** 邮件是否收到、从点击"忘记密码"到收到邮件经过多久、邮件是否进了垃圾箱。

> **第 6 步（会话保持）是本次测试最关键的一项。** 它验证的是"登录状态能否在跨境链路下持续刷新"。如果这一项不稳定，就说明托管 Supabase 方案可能不可用，必须进入规范第 5.1 节的替代方案讨论。

### 第 5 步：一次已认证的读取与一次写入

**你要做：** 在登录状态下，做一个"读取"动作（例如打开个人资料页）和一个"保存"动作（例如修改显示名并保存）。
**成功时你会看到：** 读取能显示内容；保存后刷新页面，修改**仍然存在**。
**要记录：** 两步各自的耗时。

### 第 6 步：邮件投递到常用国内邮箱

**你要做：** 用至少**两个**常用国内邮箱（例如 QQ 邮箱、163 邮箱）各注册/找回一次密码。
**成功时你会看到：** 两封邮件都能收到，且**不在垃圾箱**里。
**要记录：** 每家邮箱是否收到、是否进垃圾箱、延迟多久。这项结果决定最终选用哪个邮件服务商。

### 第 7 步：桌面与手机都要测

**你要做：** 用**电脑**和**手机**各完成一次第 1、2、4 步。
**要记录：** 设备型号与结果。

### 第 8 步：至少两种大陆网络

**你要做：** 用**一条宽带**（例如电信或联通）和**一个手机移动网络**（例如移动 4G/5G）各测一遍。
**要记录：** 分别的网络类型与结果。

### 第 9 步：换一个时间段再测一次

**你要做：** 在**第二个时间段**（建议晚间 20:00–21:00，即实际使用时段）重复第 1、2、4 步。
**要记录：** 与第一次相比，加载时间与成功率的变化。

### 第 10 步：换第二个候选区域

**你要做：** 助手把试验页面部署到第二个候选区域（例如新加坡），重复第 1–9 步。
**要记录：** 两个区域的对比结论。

### 判定标准

- 规范第 5.4 节：**"一次成功的页面加载是不够的"**；
- **任何关键流程失败，就阻止该托管方案**；
- 每个候选区域至少完成两次（两个时间段）、两种网络、两种设备；
- 结论写入本文第 9 节。

### 如何给截图脱敏

1. 用系统自带的截图工具截图；
2. 用"预览"（Mac）或"画图"（Windows）打开；
3. 用黑色矩形**完全盖住**：密码、密钥、邮箱地址、手机号、地址栏里可能带的 token 参数；
4. 盖住后再保存、再发送。

**永远不要**把密码或密钥直接粘贴到聊天里。
