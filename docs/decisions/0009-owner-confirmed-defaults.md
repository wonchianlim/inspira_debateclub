# ADR-0009：产品负责人确认的默认决策（2026-09-29）

- 状态：已接受
- 日期：2026-09-29
- 相关：`docs/architecture.md`、`docs/schema.md`、`docs/permissions.md`、`docs/dependencies.md`、`docs/deployment-regions.md`、`docs/phase-1-plan.md`

## 背景

Phase 0 的各份文档分别列出了需要产品负责人决定的事项，并且每一条都给出了一个"建议默认值"。规范第 0.2 节要求"先给推荐选项，再用简单语言说明成本、取舍与风险"。

产品负责人在 2026-09-29 的回复是：

> 建议默认值"那一列，同意

即：**同意各文档中每一条"建议默认值"**。

本文是这次确认的**唯一权威记录**。若本文与某份文档中的"待确认"表格出现不一致，以本文为准；同时那些表格会更新为已确认状态。

---

## 决定

### 1. 架构（来源：`docs/architecture.md` A-1 至 A-7）

| 编号 | 决定 |
|---|---|
| A-1 | 包管理器使用 **npm** |
| A-2 | 应用界面语言为**中文**（规范只规定与负责人沟通用中文，未规定应用界面语言；现一并采用中文界面） |
| A-3 | **暂不引入**错误追踪服务（如 Sentry）。待有明确需要时再单独提出并评估其数据存放地区。 |
| A-4 | 邮件服务商**在 Phase 0 投递测试之后再决定**，现在不锁定 |
| A-5 | 定时任务采用**与主应用共用镜像的 `cron` 容器** |
| A-6 | 新注册账号的**默认角色为 `student`** |
| A-7 | 数据库与认证的最终方案**待连通性验证后再定**（见下方"仍然未决"） |

### 2. 数据库结构（来源：`docs/schema.md` D-1 至 D-9）

| 编号 | 决定 |
|---|---|
| SCHEMA-D-1 | 取消后重新报名采用**状态回退**（同一条记录改回 `registered`），不新增第二行 |
| SCHEMA-D-2 | 不活跃账号采用**停用 + 匿名化**，**不做物理删除** |
| SCHEMA-D-3 | "一人只能在一个未解散队伍里"采用**方案 A**：`team_members.is_active` + 部分唯一索引 + 同步触发器 |
| SCHEMA-D-4 | **同意**新增 `format_positions` 查找表 |
| SCHEMA-D-5 | **同意**新增 `system_settings` 表 |
| SCHEMA-D-6 | `missing_participant` / `ready` 采用**读取时计算**，不落库 |
| SCHEMA-D-7 | ❌ **未决**：每个赛制每类分数的上下限 |
| SCHEMA-D-8 | `student_profiles.notes` **仅管理员可见** |
| SCHEMA-D-9 | ❌ **未决（部分）**：报名时间偏移、提醒时间表、各赛制 ballot 字段 |

> 补充：SCHEMA-D-9 中列举的"教练调整评分权限"已由 PERM-D-2 决定为**只读**，因此该项已关闭。

### 3. 权限（来源：`docs/permissions.md` D-1 至 D-8）

| 编号 | 决定 |
|---|---|
| PERM-D-1 | 新账号默认 `student`；裁判注册后进入 `pending` 等待批准 |
| PERM-D-2 | 教练查看学生评分为**只读**，需要时再由超级管理员按人授予修改权限 |
| PERM-D-3 | 教练可查看**全部学生**的运营数据，但不可见私人笔记以外的私人信息 |
| PERM-D-4 | **超级管理员**维护 ballot 模板 |
| PERM-D-5 | `system_settings` **无**需要对学生公开的项，仅超级管理员可读 |
| PERM-D-6 | BP 赛制下 `ballots.winner_team_id` **允许为空**，结果用 `placement` 表达 |
| PERM-D-7 | 裁判**需要**独立的签到动作 |
| PERM-D-8 | 学生**可以**撤回复核请求 |

### 4. 依赖版本（来源：`docs/dependencies.md` DEP-1 至 DEP-3）

| 编号 | 决定 |
|---|---|
| DEP-1 | 同意 `docs/dependencies.md` 第 2 节的版本提案 |
| DEP-2 | 若 TypeScript 7 与生态不兼容，**同意回退**到较旧的兼容版本，并新增 ADR 记录 |
| DEP-3 | 采用 **`.npmrc` 把 npm 缓存指向项目目录**（方案 A），绕开 `~/.npm` 的沙箱阻塞 |

### 5. Phase 1 计划中的相关项（来源：`docs/phase-1-plan.md` 第 6 节）

| 编号 | 决定 |
|---|---|
| 2 | 包管理器 npm（与 A-1 一致） |
| 3 | 默认角色 `student`（与 A-6、PERM-D-1 一致） |
| 4 | **同意** `docs/schema.md` 的关键修正 S-1、S-2、S-3、S-4、S-5、S-15、S-16 |
| 5 | 中文界面（与 A-2 一致） |
| 6 | 大陆连通性验证**尽早进行** |

## 影响

**因此被解锁的工作：**

- `docs/phase-1-plan.md` 的前置条件 B、C、H 已满足：结构修正已确认、默认角色已确认、版本提案已确认；
- P1-1 可以开始（包管理器、版本、`.npmrc` 均已确定）；
- P1-5 的身份与角色迁移可以按已确认的默认角色设计；
- P1-6 的 RLS 策略可以按已确认的权限结论落地（含"教练只读评分"）；
- P1-8 的注册流程可以确定默认角色分配逻辑。

**仍然阻塞的工作：**

| 阻塞项 | 影响范围 |
|---|---|
| 前置条件 D（连通性验证结果） | P1-12；以及 A-7 的最终数据库/认证方案 |
| 前置条件 E（付费批准） | P1-12 无法开始 |
| 前置条件 F（邮件服务商） | P1-8 的密码重置邮件投递 |
| SCHEMA-D-7、SCHEMA-D-9 | Phase 7（ballot 字段）、Phase 3（报名时间偏移）、Phase 9（提醒时间表） |
